# Daily CAPM Portfolio & OMS

미국 섹터 ETF 9개의 비중을 매일 계산하는 자산배분 백테스트와 가상 주문 관리 시스템이다.
핵심 흐름은 **과거 수익률 → CAPM 기대수익·공분산 → 거래비용을 고려한 비중·매매 판단 → 다음 거래일 체결 또는 보유 유지**다.
가상 주문 모드에서는 같은 모델로 계산한 비중을 소수 수량의 매수·매도 주문으로 바꾸고, 로컬 HTTP 서버·가상 브로커를 거쳐 수수료 차감과 잔고 반영까지 실행한다.

## 실행

Python 3.12 이상. 아래 명령은 프로젝트 루트에서 실행한다. 동봉 데이터로 실행할 때는 API 키나 데이터 다운로드가 필요 없다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[backtest,demo]'

python -m test.run --overwrite
```

성과는 터미널에 표시된다. 일별 자산·매매·비중 CSV와 지표 JSON은 `results/backtest/`에 저장되며 Git에서는 제외한다.
같은 폴더의 `backtest.xlsx`에는 `일별 계좌`, `ETF별 계산`, `매매 내역` 시트가 생성된다. ETF별 연율 기대수익·변동성·분산·목표 비중·보유 수량과 날짜별 현금·총자산·비용을 확인할 수 있다. 엑셀은 Python 계산값을 저장한 결과이며, 설정을 바꾸면 명령을 다시 실행한다.
엑셀과 `signals.csv`의 주 전략은 `capm_cost_aware`다. `decisions.csv`에는 매일 보유 유지·거래의 예상 효용과 비용, 거래 여부·이유를 기록한다. 거래하지 않는 날도 평가하며, 그날의 목표 비중은 신호일 보유 비중을 뜻한다. 다음날 가격 변화 후의 보유 비중과는 다를 수 있다. 기존 비용 무시 최적화는 `capm_mean_variance`, 해당 추정값·목표 비중은 `baseline_signals.csv`에 남겨 비교한다. 두 전략 모두 실제 체결 비용을 차감한다.
`--output results/experiment-02`로 실험 결과를 따로 저장할 수 있다. 데이터 수집은 [data.py](test/data.py), 설정은 [daily-capm.json](configs/daily-capm.json)에 있다.

입력 데이터는 `datasets/`에 모아둔다. `adjusted_close.csv`는 가격, `factors.csv`는 RF 등 일별 자료, `raw/`는 원본, `manifest.json`은 출처·검증 정보다.

거래 CSV를 다시 읽어 자산·비용을 검산하려면 `python -m test.audit`, 모의 주문을 시연하려면 `python -m oms.demo`를 실행한다.
기존 학습용 API는 `python -m uvicorn oms.api:create_app --factory --host 127.0.0.1 --port 8000`으로 실행한다.

## 가상 주문 실행

첫 번째 터미널에서 10만 달러 가상 계좌 서버를 실행한다. 학습용 DB와 분리해 `data/paper-fractional.sqlite3` 및 브로커 DB에 기록한다. 이전 정수 수량 시연의 `data/paper.sqlite3`는 그대로 보존한다.

```bash
python -m uvicorn oms.api:create_paper_app --factory --host 127.0.0.1 --port 8001
```

두 번째 터미널에서 같은 가상환경을 활성화하고 실행한다.

```bash
python -m oms.paper
```

전 거래일까지의 252일 자료와 신호일 가격으로 평가한 현재 보유 비중으로 거래를 판단한다. 보유 유지보다 비용 차감 후 기대 효용이 높으면 수수료 차감 후 투자금 계산 → 소수 목표 수량에서 기존 보유 수량 차감 → 매도 후 매수 → 브로커 체결 → OMS 상태 대사 → 현금·보유 수량 검산 순서로 실행한다. 최초 투자와 25% 비중 한도 초과의 조정은 의무 거래다. 유지 판단이면 주문을 만들지 않는다. 비용 차감 후 투자금은 백테스트와 같은 `allocate_after_cost` 함수로 구한다. `/orders`에 접수된 `NEW` 주문은 체결 확인 후 `FILLED`가 된다.

수량·가격은 소수 8자리까지 받으며, API에 `"quantity": "1.25"`, `"limit_price": "100.25"`처럼 문자열로 보낸다. 내부 계산은 `Decimal`, DB 저장은 십진 문자열을 사용한다. 수수료는 매수·매도 체결금액 각각 0.05%(5 bps)이며, 체결마다 기록하고 현금에서 차감한다. 주문당 한도 외에 가용 현금·매도 가능 수량을 확인하고, 미체결 매수의 수수료까지 포함해 현금을 예약한다. 부분 체결과 같은 체결의 재수신에도 수량·수수료를 중복 반영하지 않는다. `/account`의 `total_fees`는 누적 수수료, `positions`는 소수 보유 수량이다.

API 문서는 [localhost:8001/docs](http://127.0.0.1:8001/docs), 잔고와 보유 수량은 [localhost:8001/account](http://127.0.0.1:8001/account)에서 확인한다. 결과 JSON은 `results/paper/`에 저장한다. 날짜를 지정하려면 `python -m oms.paper --date 2025-12-30`처럼 실행한다.

기본 가격 날짜는 동봉 데이터의 마지막 거래일인 2025-12-31이다. 전일 신호와 백테스트와 같은 조정 종가를 사용하고, 이 시세를 소수 8자리로 고정해 지정가에 즉시 전량 체결하는 오프라인 시연이다. 수량도 소수 8자리로 내림하므로 미세한 현금 잔액이 생긴다. 수량은 조정가격 기준의 모의 단위이며 실제 증권사 주식·배당 처리를 재현하지 않는다. 실시간 가격·호가·유동성·슬리피지와 현금 이자는 제외한다. 다른 날짜로 실행하면 기존 가상 보유분에서 다시 리밸런싱한다. 전체 2010~2025년 OMS 재생은 아직 실행하지 않았다.

체결 기록을 지우지 않고 재시작할 수 있다. 구 정수·센트 DB는 읽을 때 Decimal 저장 형식으로 변환하며, 과거 체결의 수수료는 0으로 유지한다. 미확정 주문이 있으면 가상 주문 실행을 멈추며, API에서 상태 대사 또는 취소 후 다시 실행한다.

## 기간 재생과 검산

별도 계좌에서 과거 거래일을 순서대로 실행한다. 첫 번째 터미널에서 서버를 띄운다.

```bash
python -m uvicorn oms.api:create_replay_app --factory --host 127.0.0.1 --port 8002
```

두 번째 터미널에서 실행한다. 기본 범위는 설정의 시작일부터 그 달의 말일까지다.

```bash
python -m oms.replay
```

같은 일별 목표 비중과 거래·보유 판단으로 백테스트 원장과 OMS를 각각 실행한다. 기본 전략은 `capm_cost_aware`이며 `--strategy capm_mean_variance`로 기존 전략을 선택할 수 있다. 전략 신호는 연구 원장에서 생성하며 OMS와 독립적으로 다시 최적화하지 않는다. OMS는 주문·가상 브로커 체결·상태 대사 API를 거쳐 보유 수량과 현금을 만든다. 거래 전에는 `/simulation/sessions/{day}`로 남은 현금에 일별 RF를 적용한다. 같은 거래일을 재요청해도 이자를 중복 반영하지 않고, 날짜 역행과 미확정 주문이 있는 상태의 날짜 변경은 거절한다. `/account`의 `as_of_date`는 재생 거래일, `total_interest`는 누적 현금 이자다. 주문의 `created_at`은 실제 프로그램 실행 시각이다.

매일 총자산·현금·누적 수수료·ETF별 보유 수량을 대조하며, 허용 오차는 금액 0.01달러와 수량 0.00001단위다. OMS는 가격·수량을 소수 8자리로 제한하므로 반올림·내림에 따른 미세한 차이가 있다. 불일치가 생기면 그 날짜에서 멈춘다. `results/replay/daily.csv`는 일별 비교, `orders.csv`는 실제 OMS 주문·체결 내역, `summary.json`은 검산 결과다.

기존 전략은 2010-01-04~2010-01-29의 **19거래일·171건 체결**을 검증했다. 최종 총자산은 **$93,876.35**, 누적 수수료는 **$142.923653**, 날짜별 총자산 최대 차이는 **$0.00003124**였다. 거래비용을 고려한 전략도 별도 계좌에서 2010-01-04~2010-03-31의 **61거래일·153건 체결**을 검증했다. 보유 유지일에는 주문을 보내지 않으며, 최초 투자·비용 대비 효용 개선·비중 한도 조정을 모두 포함한다. 전체 기간 OMS 재생은 아직 실행하지 않았다.

재생 계좌는 [localhost:8002/account](http://127.0.0.1:8002/account)에서 확인한다. `data/replay.sqlite3`와 별도 브로커 DB에 보관하며 기존 8001 시연 계좌에 영향을 주지 않는다. 범위는 `--start`와 `--end`로 바꾼다. 전체 기간은 `python -m oms.replay --end 2025-12-31 --output results/replay-full`로 지정할 수 있지만 아직 실행하지 않았다.

재생은 사용하지 않은 계좌와 비어 있는 결과 폴더에서 시작한다. 재실행이나 다른 기간 실험에는 서버의 `OMS_DB_PATH`로 새 DB 경로를 지정하고 CLI의 `--output`으로 새 결과 폴더를 지정한다. 기존 계좌·결과를 자동으로 초기화하거나 중간부터 재개하지 않는다.

## 모델의 기준

- 대상: XLB(소재), XLE(에너지), XLF(금융), XLI(산업재), XLK(기술), XLP(필수소비재), XLU(유틸리티), XLV(헬스케어), XLY(경기소비재).
- 기대수익: `평균 RF + 베타 × 평균 시장 초과수익`을 연율화한다. 시장 대용치는 SPY다.
- 목적함수: `max h × (μᵀw − λ/2 × wᵀΣw) − c × Σᵢ|wᵢ − w현재,ᵢ|`. 비중 합 100%, 공매도 없음, 목표 비중은 ETF당 최대 25%, λ=5다. μ·Σ는 연율, `h = cost_horizon_days / 252`, `c = fee_bps / 10000`다. 기본 비교 기간은 매일 판단하는 전략에 맞춰 **1거래일**이다. 252일 추정 구간과 비용을 회수한다고 가정하는 기간은 서로 다르다.
- 매매 판단: 가격 변동이 반영된 신호일의 실제 보유 비중과 비교한다. 기간 내 기대 효용 개선이 예상 거래비용을 초과할 때만 거래하며, 그 외에는 수량을 그대로 둔다. 최초 전액 투자와 신호일에 관측된 25% 비중 한도 초과의 조정은 우선한다. 비중 변화가 생기는 다음날 종가 체결이므로 장중·모든 시점의 한도를 보장하지는 않는다.
- 공분산: 252일 표본 공분산을 연율화하고 대각 행렬로 10% 축소한다.
- 시점: t일 종가로 비중 계산 → t+1일 종가 체결 → 이후 수익부터 새 비중에 반영한다.
- 비용: 매수·매도 금액 각각 0.05%. 목적함수의 비용은 신호 시점의 `c × 비중 변화 절댓값 합` 추정치다. 비중 10%를 팔아 다른 ETF 10%를 사면 비용은 자산의 0.01%다. 실제 비용은 다음날 가격과 비용 차감 후 투자금으로 별도 계산하므로 추정치와 다를 수 있다. 비용 차감 후 투자금을 계산해 차입을 방지한다.

## 백테스트 결과와 범위

2010-01-04~2025-12-31의 4,024거래일, 초기 자산 $100,000, 매수·매도 각각 5 bps 기준이다. 아래 수익률은 모두 실제 거래비용 차감 후 값이다.

| 지표 | 기존 CAPM 평균·분산 | 거래비용 고려 CAPM |
| --- | ---: | ---: |
| 최종 자산 | $447,366.20 | $639,503.13 |
| 누적 수익률 | 347.37% | 539.50% |
| 연평균 복리수익률(CAGR) | 9.84% | 12.32% |
| Sharpe ratio | 0.573 | 0.689 |
| 최대 낙폭 | -35.64% | -35.21% |
| 누적 수수료 | $26,433.05 | $587.11 |
| 거래한 날(최초 투자 포함) | 4,024일 | 181일 |
| 연평균 회전율(매수+매도) | 1,441.27% | 24.37% |

새 전략은 3,843일 보유를 유지했다. 181일의 거래는 최초 투자 1일·순효용 개선 49일·비중 한도 조정 131일이다. 매일 계산하지만 매일 거래하지는 않는다. 수수료 절약과 달라진 보유 비중 경로의 효과가 함께 반영된 결과다.

같은 기간 동일비중의 CAGR은 **12.44%**, 최소분산 **11.63%**, SPY 보유 **13.92%**였다. 새 전략도 이 실험에서 SPY나 동일비중을 웃돌지 못했다. 위험 회피도·비용 비교 기간을 성과에 맞춰 탐색하지 않았다. 결과는 `python -m test.run --output results/cost-aware`와 `python -m test.audit --results results/cost-aware`로 재현·검산한다. 이미 결과가 있으면 새 출력 경로를 사용한다.

5개 전략 각각의 4,024일 자산과 거래비용을 거래 CSV에서 다시 계산해 확인했다. 거래비용 고려 전략은 신호일 보유 비중·예상 비용·거래 이유도 대조했다. 별도로 2자산 격자 계산과 최적화 결과를 비교하고, 미래 가격·RF를 바꿔도 이전 신호가 바뀌지 않는지 확인했다.

가격은 Yahoo 조정 종가, RF는 Kenneth French 일별 자료다. 원본과 가공 데이터 해시를 검증한다. 조정가격의 분수 단위 연구 원장이므로 실제 주식 수량·체결 이력은 아니다. 현재 선택한 ETF 집합과 사후 수정 데이터에 대한 한계가 있으며 세금·호가·시장 충격은 제외했다. 마지막 평가액에 최종 청산 비용은 적용하지 않는다.

백테스트와 가상 주문은 같은 추정·최적화·거래 판단 함수를 사용한다. 단일 날짜 시연은 현재 계좌로 다시 판단하고, 기간 재생은 연구 원장의 일별 신호·거래 여부를 공유한다. 둘 다 거래 CSV를 주문으로 복사하지 않고 목표 비중에서 주문 수량을 계산한다. 실제 증권사 연결은 없다.

## 이력서 요약

- CAPM 기대수익·공분산과 거래비용을 고려해 미국 섹터 ETF 9개의 비중과 거래 여부를 매일 결정하는 시스템 구현.
- 체결 지연·거래비용을 반영한 2010~2025년 백테스트로 SPY·동일비중·최소분산 전략 성과 비교.
- 소수 수량과 거래비용을 반영한 주문을 FastAPI·SQLite 가상 OMS의 매수·매도·체결·잔고 조회에 연결.
